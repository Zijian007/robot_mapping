# 融合栅格更新

`_ray_native` API v3 的 `grid_update` 将最近回波筛选、射线限额、命中/空闲去重、
分值累积、格子状态刷新及脚下临时空闲先验合并为一次 C++ 调用。
直接更新 Python 已分配的 `int8` 分层分值和 `int16` 二维状态数组，不返回大批格子索引，
也不复制整张分值图。遍历和更新期间释放 GIL，不持有跨调用的 NumPy 缓冲区指针。

Python 继续验证观测、过滤零长度射线、计算地图扩容范围，并管理栅格分配与扩容。
方位角、高度和起点分组保留 NumPy 运算，避免改变角度边界和 round-to-even 的浮点行为。
原有 Python/NumPy 证据更新路径保留，供没有兼容扩展的环境及逐观测等价性验证使用。

## 语义与并发边界

- 范围内所有回波提供命中证据，最近射线筛选只限制空闲证据；分组相同、距离相同时保留
  最早输入，限额顺序保持与原先 `lexsort` / `linspace` 路径一致。
- 同次观测每个高度格只更新一次；先标记命中，遍历时跳过已命中的格子。
  分值仍在 `[-4,8]` 内饱和，命中加 2、穿过减 1。
- 任意一层达到 3 则占用；所有层都小于 0 才为空闲，其余为未知。
  保留部分顶层高度、闭合的最高高度边界，以及独立的传感器起点。
- 旧脚下先验按原来的矩形范围恢复证据状态，再绘制当前圆形先验；任何正分值都阻止
  先验把未知格涂为空闲。空观测和零长度观测不迁移先验。
- 更新目标必须是可写、C 连续的准确类型数组；绑定禁止隐式转换目标数组，避免写到副本。
  `OnlineMap` 继续持锁保护摄入与快照；独立使用 `RayOccupancy2D` 时调用方需串行访问同一对象。
  回环重建使用独立栅格，仍按原事务发布。

完整证据规则和适用边界见 [栅格与点云清理](mapping.md)。

## 2026-11-09 离线测量

同一主机串行执行旧 API v2 实现和新 API v3 实现各 9 轮；Python 参考实现执行 3 轮。
输入为同一组 12 次录包观测，OpenBLAS 固定 1 线程，使用默认栅格配置。
最终栅格为 `849 × 675 × 11` 层，5,307 个占用格、456 个空闲格。

| 栅格观测更新时间 | 原实现（已有 C++ 遍历） | 融合内核 | Python 参考路径 |
|---|---:|---:|---:|
| P50 | 31.83 ms | 15.86 ms | 54.74 ms |
| P95 | 38.78 ms | 21.41 ms | 63.41 ms |
| P99 | 48.57 ms | 24.17 ms | 67.26 ms |

新路径的角度/起点分组 P50 为 3.21 ms，融合 C++ 更新为 8.19 ms，扩容调用为 0.36 ms；
扩容 P95 为 5.81 ms。原路径分组筛选 P50 为 7.18 ms、射线遍历接口为 8.44 ms，
其余验证、命中去重、数组分值与状态更新约占 14.28 ms。各阶段分位数不能直接相加。
收益主要来自合并更新和减少排序、去重及中间数组；扩容的尾部耗时仍存在。

计时包含整个 `ingest_rays` 调用，不含文件解码、地图坐标转换、摘要计算或 FAST-LIO2。
逐次观测后分值数组、二维状态和地图参数的摘要在三个后端间完全一致。
这是局部离线测量，受共享主机负载影响，不代表整套建图吞吐量或实机采集稳定性。
本轮没有连接机器人。

## 验证与复现

原生完整回归 200 项通过；屏蔽扩展后的参考路径 179 项通过、21 项原生专用测试跳过。
新增对照覆盖射线限额 1/2/19/64、边界高度、float32/非连续输入、扩容、先验迁移和清空；
已有回环测试核对分层分值与二维状态重建，并覆盖重建期间到达的新观测。
低层接口测试验证错误形状、类型、只读及非连续目标缓冲区在更新前被拒绝。
源码分发包另行检查包含 `grid_update.hpp`。

从核心包目录运行：

```bash
.venv/bin/python setup.py build_ext --inplace
OPENBLAS_NUM_THREADS=1 PYTHONPATH=src .venv/bin/python scripts/benchmark_grid.py \
  --backend native \
  --observations artifacts/baselines/native-rays-20261108/observations.npz \
  --output ../robot_mapping_gdk/artifacts/evaluations/grid-native-20261109/native.json \
  --repeats 9
```

`--backend python` 运行参考路径；`--backend legacy --legacy-root DIR` 在独立进程中加载
明确保存的旧 `ray_grid.py` 与匹配的 `_ray_native*.so`。本次旧代码和三个后端结果保存在
`robot_mapping_gdk/artifacts/evaluations/grid-native-20261109/`，不作为运行依赖。
输入 SHA-256：`24d8a633720bdc138339a0cee513e17a9265b2b492567c1db73c28f2ef9e0356`。

安装与锁定环境更新遵循 [开发指南](development.md)。融合更新需要 `grid_backend: cpp`、
API v3 及以上；管理环境验证会实际执行占据确认与射线清空。后续
[点云预处理](native-preprocess.md) 将当前运行环境升级至 API v4。
